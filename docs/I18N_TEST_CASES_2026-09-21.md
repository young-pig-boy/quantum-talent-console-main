# 中译英（E Mode）现状总结 · 中台录入规范 · 前端验证测试用例

> 2026-09-21 · 覆盖范围：showcase（候选人前台）+ console（内部中台）+ Supabase `job_publications`
> 用途：① 交代当前中译英的实现边界；② 说明新建岗位在中台要怎么填前台才不会出问题；③ 提供可直接执行的测试用例清单。

---

## 一、现状总结

### 1.1 一句话架构

没有引入 i18n 框架，走的是**自研轻量双语层 + 数据库冗余英文字段**：

- **固定 UI 文案**（导航、页脚、按钮、区块小标题）：客户端组件 `EText / EnOnly / ZhOnly / EValue`，中英写死在代码里，切换靠内存态 `mode: 'zh' | 'en'`（导航栏「中 / E」，**不持久化**，刷新回中文）。
- **岗位动态内容**（标题、方向、职级、摘要、学历、经验、职责、要求、标签、薪资）：DB 里为每个字段配一列 `*_en`，前台英文模式**逐字段独立取值**，空值回落中文。
- **有限枚举值**（城市、学历、经验、状态词）：代码里的映射表兜底（`localized-helpers.ts`）。
- **赛道文案**：静态数据 `tracks.ts` 自带 `englishName / overviewEn / …`。

### 1.3 英文模式的取值优先级（每个字段独立判定）

```
1) DB 英文列有值            → 用英文列
2) 英文列为空 → 代码映射表  → 城市 / 学历 / 经验 / 状态词（待确认、面议…）
3) 仍未命中 → 经验数字兜底  → "3-5年"→"3-5 years"、"5年以上"→"5+ years"、"3年"→"3 years"
4) 仍未命中 → 原样输出中文   （不猜测、不机翻）
```

**映射表覆盖范围（即"不填英文列也可能显示英文"的值）**

- 城市/地区：北/上/广/深 + 主要地级市 + 省份 + `全国 / 海外 / 远程 / 线上 / 不限`
- 学历：`硕士及以上 / 硕士 / 本科 / 本科及以上 / 统招本科 / 大专 / 博士 / 博士及以上` 等 11 条
- 经验：25 条历史真实取值（如 `封装或半导体行业5年以上`）+ 纯数字型格式
- 状态词：`待确认 / 待从详情页确认 / 未明确 / 面议 / 不限 / Remote`

**映射表明确不覆盖、必须靠 `*_en` 列的内容**：岗位标题、方向、职级、摘要、职责正文、要求正文、技术标签、薪资长句。

## 二、新建岗位在中台怎么设置，前台才不会出问题

### 2.1 完整链路（必须按这个顺序）

先说清楚两个概念，后面的步骤就好懂了：

- **内部岗位**（菜单「岗位管理」）：给内部用的档案，**大部分字段不会对外**。会带到前台的只有 4 个：岗位名称（→公开标题初稿）、城市（→公开城市）、岗位描述 JD（→公开职责初稿）、硬性要求（→公开要求初稿）。内部薪资、排除规则、内部备注、运营信息**永远不对外**。
- **公开岗位**（菜单「公开岗位」）：真正显示在前台的记录，**所有英文都在这里填**。内部岗位的新建表单里没有任何英文输入框，这是设计如此。

**逐步操作（所有测试用例都走这条路径，只是填的内容不同）：**

```
第 1 步  新建内部岗位
   左侧菜单「岗位管理」→ 岗位列表页点「创建岗位」→ 进入「新增内部岗位」表单
   必填：岗位名称 * 、所属公司 *（下拉选择）
   建议填：城市（会继承到公开岗位）
   可随意/留空：内部薪资、岗位描述(JD)、硬性要求、排除规则、内部备注、运营信息
   → 点底部「创建岗位」按钮，自动跳到内部岗位详情页

第 2 步  开始招聘
   内部岗位详情页右上角 → 点「开始招聘」（状态从 草稿 → 招聘中）
   ※ 不点这步，后面「创建公开岗位」按钮不会出现

第 3 步  创建公开岗位
   同一页右上角 → 点「创建公开岗位」→ 提示"公开岗位创建成功"
   页面下方出现公开岗位卡片（状态：草稿）

第 4 步  编辑公开岗位（填中英文的地方全在这里）
   点进该公开岗位（或左侧菜单「公开岗位」→ 列表里点标题）
   → 右上角点「编辑」→ 按第三节的用例表格逐项填写 → 点「保存」

第 5 步  发布
   同一页右上角 → 点「发布」→ 确认弹窗 → 前台立即可见
```

> 为什么要第 4 步重新填职责/要求：内部岗位的 JD 是一大段自由文本，而前台职责是 **01/02/03 编号列表**。建议在公开岗位编辑页用「岗位职责」「任职要求」的逐条输入框（点添加一条一条录）重新录入，保存后会覆盖从 JD 带过来的文本。
>
> 为什么不直接粘贴 URL 验证：slug 由中文标题生成、含中文，直接粘 URL 可能 404；请始终从列表/首页点进去。

### 2.2 发布时会被拦住的硬规则（提前知道，少踩坑）

1. 公开标题、slug、site_id 必须有（site_id 自动取一个 active site，通常不用管）。
2. **职责 或 任职要求至少有一个**，否则发布报 `At least one of responsibilities or requirements is required`。
3. **赛道必须是四大赛道之一或留空**；填了别的值 → 编辑页顶部出现「需要重新选择赛道」，发布被阻止。
   - 四大赛道：`超导量子 / 离子阱 / 光量子 / 量子通信与测量`（值分别是 `superconducting / ion-trap / photonics / communication-sensing`）。
4. **底层内部岗位必须是 recruiting**，否则发布/重新发布报 `Cannot publish: underlying job is not recruiting`。
5. 「急招」只能对**已发布**岗位开启（先发布再开急招），且截止时间必须晚于开始时间。

### 2.3 要让英文模式「一个中文都不剩」，必须填满这 10 个框

编辑态字段顺序（照这个顺序填最不容易漏）：

| 区块 | 填写顺序 |
|---|---|
| 岗位归类 | 所属赛道（单选）→ 方向 (Direction) → **方向英文 (Direction EN)** |
| 岗位运营 | 急招 / 精选（开关，非翻译项） |
| 公开信息 | 公开标题 → **公开标题英文 (Title EN)** → 城市 → 薪资展示 → **薪资展示英文 (Salary EN)** → 职级 → **职级英文 (Seniority EN)** → 学历要求 → **学历要求英文 (Education EN)** → 经验要求 → **经验要求英文 (Experience EN)** → 一句话摘要 → **一句话摘要英文 (Summary EN)** → 技术标签 → **技术标签英文 (Tags EN)** |
| 岗位职责 | 中文职责列表 → **岗位职责英文 (Responsibilities EN)**（条数保持一致） |
| 任职要求 | 中文要求列表 → **任职要求英文 (Requirements EN)**（条数保持一致） |

**填写规范（保证前台不错位）**

- **标签英文必须与中文一一对应、顺序一致**（按索引取值，不按内容匹配）。中文 3 个、英文只填 2 个 → 前 2 个英文、第 3 个回落中文；不会错位、不会丢。
- **职责/要求英文条数建议与中文一致**；英文整体为空时前台整体回落中文（不做逐条混合）。
- 英文留空 = 回落中文，**不是**留白或报错。所以"先发中文、英文后补"是安全的。
- 薪资是唯一"没有映射表兜底"的展示字段：`面议 / 待确认` 这类中文若不填 Salary EN，英文模式仍显示中文。

### 2.4 为什么新岗位不会把前台弄坏（机制层面）

1. **列已全部存在**（002–006 均已在正式库执行），前台探针（`en-columns.ts`）取"满配"字段白名单，直接带上 10 个 `*_en` 列查询。
2. 即使某个环境迁移没跑，探针会**自动降级**到低档白名单（满配→005→004→003→002→基础），列表照常出数据，不会 500；降级缓存 60 秒 TTL，迁移执行后自动升级，无需重启。
3. 新岗位英文列全 NULL → 前台逐字段回落中文，**不空白、不破版、不报错**。
4. 城市会被二次标准化（前台 + 中台都做）：北京/上海/广州/深圳保留城市；其他城市→省份（`武汉`→`湖北`）；特殊值 `待确认 / 全国 / 海外 / 远程 / 线上 / 不限` 原样保留。所以英文模式看到 `Hubei` 而不是 `Wuhan` 属**既有对外策略**（不暴露具体城区），不是 bug。
5. 未选赛道的岗位：列表卡片不显示赛道英文小字，也不进任何赛道页的相关岗位；其余信息正常显示。

### 2.5 目前录入侧已知的 4 个坑（**我没有改代码，等你决定**）

| # | 现象 | 影响 | 建议 |
|---|---|---|---|
| A | **清空**英文标签/职责/要求后保存，不会真正清空（这三项在 payload 中为空时不下发，后端保留旧值；其余英文文本框会正常清空） | 想测"清空→回落中文"会误判为 bug | 允许下发空值即可修复（1 行×3 处） |
| B | 保存偶发报 `JobPublication not found` | 该错误其实可能是任意 DB 错误被 `findById` 统一吞成 Not Found（缺列、权限等） | 改为原样抛出 DB 错误 |
| C | 创建公开岗位时不预填英文（也不给填） | 每次都要在编辑页手填 10 项 | 可让创建时支持带入 overrides，或编辑页加「复制中文到英文」按钮 |
| D | slug 由中文标题生成，含中文 | 站内点击跳转正常；**直接粘贴 URL 到浏览器可能 404**（Next dev 对中文 slug 的行为） | 验证请从列表/首页点击进入 |

## 三、测试用例（在中台执行 → 到前台观察）

**怎么用这一节**：每个用例都从上面 2.1 的「第 1 步 ~ 第 5 步」完整走一遍（也就是你问的：先去「岗位管理」新建内部岗位 → 开始招聘 → 创建公开岗位 → 去公开岗位编辑填表 → 发布）。每个用例只列**要填的内容**和**前台应该看到什么**，操作动作完全相同。

**内部岗位表单怎么填（每个用例都一样，只有岗位名称加个编号区分）**：

| 内部岗位表单字段 | 填写值 | 说明 |
|---|---|---|
| 岗位名称 * | `量子芯片封装工程师-TC01`（编号换成对应用例号） | 会成为公开标题初稿，后面在公开岗位编辑页改 |
| 所属公司 * | 下拉任选（如 图灵量子） | 仅内部可见，不影响前台 |
| 城市 | 用例表格里「城市」一栏的值 | 会继承到公开岗位 |
| 内部薪资 | 随意或留空（如 `60-100K·15个月`） | **永不对外**，和前台「薪资展示」无关 |
| 岗位描述 (JD) | 随意或留空 | 只是初稿，第 4 步会用列表框重填 |
| 硬性要求 | 随意或留空 | 同上 |
| 排除规则 / 内部备注 / 运营信息 | 留空 | 永不对外 |

**每个用例的公开岗位要填什么 → 见下面各用例的表格。**

建议为每个用例单独走一遍完整流程（新建 1 个内部岗位 + 1 个公开岗位），不要复用同一个岗位反复改——因为存在「清空英文保存不生效」的已知问题（见 2.5 坑 A），复用会让回落验证失真。

### TC-06 运营状态（急招 / 精选 / 未发布 / 下架）

1. **未发布（draft）**：编辑填完后先不发布 → 前台 `/opportunities` 列表与详情页都**看不到**该岗位（直接访问详情 URL 应 404/not-found）。
2. **发布后**：立即出现在列表；项目编号（Job ID）显示正常（英文 `Job ID`，中文 `岗位编号`）。
3. **急招**：发布后回中台开启急招（设开始/截止时间）→ 列表与详情出现 `Urgent` / `急招` 徽章；把截止时间设为过去 → 徽章消失（不算 bug）。
4. **精选**：中台点「设为精选」→ 列表卡片出现 `Featured` / `精选` 徽章，并出现在首页精选区块（该区块 JobCard 字段同样是英文）。
5. **下架**：中台点「下架」→ 前台立即消失；已开启的急招自动失效。

## 四、执行与记录建议

**操作卡住了？常见卡点速查**

| 现象 | 原因 | 处理 |
|---|---|---|
| 内部岗位详情页没有「创建公开岗位」按钮 | 状态还不是「招聘中」 | 先点「开始招聘」 |
| 公开岗位编辑页没有「编辑」按钮（灰色） | 当前账号无 `publication_edit` 权限 | 找 Team Lead 开权限 |
| 点「发布」报 `At least one of responsibilities or requirements is required` | 职责、要求都是空的 | 编辑态至少填一个（中文即可） |
| 点「发布」报「岗位赛道值无效」 | 赛道是脏值 | 编辑态重新选四大赛道之一或「未归类」 |
| 点「发布」报 `Cannot publish: underlying job is not recruiting` | 内部岗位被暂停/关闭 | 回内部岗位恢复「招聘中」 |
| 前台看不到刚发布的岗位 | ① 看的是生产站而不是 Deploy Preview；② 英文模式缓存未刷新 | ① 换 Deploy Preview URL；② 刷新页面 |
| 中文 slug 详情页直接粘贴 URL 404 | dev 环境对中文 slug 的行为 | 从列表/首页点击进入 |

**每跑完一个用例，按下表各看一眼（建议截图留档）**：

| # | 检查位置 | 关注点 |
|---|---|---|
| 1 | 中台 `/publications/{id}` 只读态 | 各 `…(EN)` InfoField 有值；标签中英并排 `/` 显示；职责要求下方有 `Responsibilities (EN)` / `Requirements (EN)` 小节 |
| 2 | `/opportunities` 列表卡片 | 标题 / 方向·职级 / 摘要 / 标签 / Location / Pay / Education / Experience |
| 3 | 首页岗位区块 | 同上（同一组件） |
| 4 | 详情页 `/jobs/{slug}` | H1 + 5 个 meta 行 + 赛道/方向 chip + 标签 + Overview / Responsibilities / Requirements |
| 5 | 详情页底部 Related Positions | 同赛道岗位的英文标题与英文城市 |
| 6 | 赛道页 `/tracks/{id}` | 赛道名/概述 + `Interested in …?` + 相关岗位列表 |
| 7 | 中文模式回切 | 中文必须与验收前一致（改英文字段不得影响中文展示） |

**验证环境提醒**

- 英文模式切换：导航栏「中 / E」两个按钮，**刷新即回中文**，属已知设计（无持久化）。
- 验证的是 **Deploy Preview URL**（代码推的是 `preview-update` 分支，Netlify 生产站发布自 `main`），否则看的是旧代码。
- 详情页请从列表点击进入；中文 slug 直接粘贴 URL 在 dev 环境可能 404（坑 D）。

## 五、待你确认的三处改进（都还没动代码）

1. **清空英文不生效**（坑 A）：英文标签 / 职责 / 要求清空后保存，旧英文仍保留。→ 建议改为下发空值，与其它英文文本框行为一致。
2. **`JobPublication not found` 假错误**（坑 B）：把 DB 错误原样抛出，避免误判成"岗位不存在"。
3. **新建公开岗位不预填英文**（坑 C）：可在创建时带入，或编辑页加「从中文复制」按钮，减少手填 10 项的成本。

另外两个可选项，成本都低，你定：

- 薪资增加映射表兜底（`面议 → Negotiable`、`待确认 → To be confirmed`），减少一个必填项。
- 标注哪些字段属于"必须填英文"（标题/方向/职级/摘要/薪资/标签/职责/要求/学历/经验 的自由文本部分）——可在中台标签上加「*」提示。
